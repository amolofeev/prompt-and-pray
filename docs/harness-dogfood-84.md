## Наблюдаемость

Каждая фаза исполнялась как вложенная субагентская сессия opencode через
Task tool: оркестратор вызывал роль (`subagent_type: delivery`,
`team-lead-go`, `developer-go`), роль возвращала результат строго в виде
YAML-отчёта по контракту (см. `docs/harness-agents.md`), а delivery
направлял следующий маршрут.

Важно (честная оговорка): вложенность субагентских сессий и последовательность
вызовов через Task tool наблюдал оркестратор в интерактивной сессии opencode.
developer-go на своей фазе проверяет только побочные эффекты командами
(файлы, git-состояние, состояния issues через gh) и не имеет доступа к
журналу вложенных сессий. Процесс считается видимым в opencode по
критериям приёмки #84: цепочка отработала end-to-end, вершина закрыта,
вложенные сессии отражены в истории интерактивной сессии оркестратора.
