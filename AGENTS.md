# AGENTS.md

## Работа с задачами

Задачи живут как GitHub Issues, работа идёт через `gh` и роли-субагенты.
Роли не завязаны на конкретный трекер: они используют нейтральный «инструмент
работы с задачами», а какой именно применять — определяет этот манифест.

Для этого репозитория (источник задач — GitHub Issues):

- skill `harness-workflow` (`.opencode/skills/harness-workflow/SKILL.md`) —
  конвенции: чек-лист атомарности, рёбра `Depends on:`/`Blocks:`, ready set,
  этапы работы;
- skill `tasks-gh` (`.opencode/skills/tasks-gh/SKILL.md`) — операции с
  задачами (чтение/создание/рёбра/close).

Роли — в `.opencode/agent/`; человекочитаемая спека — `docs/harness-agents.md`.

## Модель исполнения

Контур — «дерево рекурсивного делегирования»: каждый узел-роль — оркестратор
своего поддерева, вызывает разрешённых детей и возвращает агрегат наверх.
Specificator — общий hidden-субагент обогащения контекста. Реестр типов узлов
и разрешённых детей (`permission.task`) — в спеке `docs/harness-agents.md`.

## AI-контент обязан иметь префикс `[AI]`

Весь AI-сгенерированный контент (commit-сообщения, описания и комментарии
issues/PR) помечается префиксом `[AI]`, чтобы было видно, где работал человек,
а где AI.

Формат коммита:

```text
[AI] #<id> <краткое резюме задачи>


<подробное объяснение: что сделано и почему. Пункт на строку.>
```

`#<id>` обязателен в каждом коммите сразу после `[AI]`, до текста — включая
post-review (рефлексию) и коммиты-правки правил. Если коммит не относится ни
к какой задаче и не является рефлексийным — сначала заведи meta-issue
(`gh issue create -l meta ...`) и сошлись на него.

Формат комментария/описания issue или PR:

```text
[AI] <краткое резюме>

<подробное содержимое>
```
