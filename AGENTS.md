# AGENTS.md

## Работа с задачами через gh

Задачи живут как GitHub Issues, вся работа идёт через CLI `gh`. По команде вида
«реши задачу N», «возьми в работу N», «solve issue N» иди по фазам:

1. **Team Lead** — прочитать задачу (`gh issue view <n>`, `gh issue view <n>
   --comments`) и проверить атомарность: один исполнимый шаг с понятным
   deliverable, результат измерим/проверяем без других задач, дальше не дробится.
   Составную задачу раскрыть в сабтаски — настоящие sub-issues через
   `gh issue create --parent <root>` (не лейблы), проставить рёбра зависимостей
   `Depends on: #<n>` / `Blocks: #<n>` в теле задачи.
2. **Scrum Master** — перед взятием вычислить ready set: все блокеры-ребра
   (referenced-issues из `Depends on:`) должны быть закрыты; проверка —
   `gh issue view <n> --json state`. Открытый блокер → задача в работу не
   берётся, это ожидание.
3. **Developer** — изучить код, реализовать, проверить, закоммитить (AI-формат,
   см. ниже), запушить, закрыть задачу: `gh issue close <n> --comment "..."`
   с [AI]-резюме.

Каждый этап/задача завершается push в origin (`git push`). Закрытие вершины может
открыть новые задачи — вернись к Team Lead.

## AI-контент обязан иметь префикс `[AI]`

Весь AI-сгенерированный контент (commit-сообщения, описания и комментарии
issues/PR) помечается префиксом `[AI]`, чтобы было видно, где работал человек,
а где AI.

Формат коммита:

```text
[AI] #<id> <краткое резюме задачи>


<подробное объяснение: что сделано и почему. Пункт на строку.>
```

`#<id>` обязателен в каждом коммите сразу после `[AI]`, до текста — включая
post-review (рефлексию) и коммиты-правки правил. Если коммит не относится ни
к какой задаче и не является рефлексийным — сначала заведи meta-issue
(`gh issue create -l meta ...`) и сошлись на него.

Формат комментария/описания issue или PR:

```text
[AI] <краткое резюме>

<подробное содержимое>
```
